# Available Tools

Call `help({ tool_name: "<name>" })` to read the full Markdown documentation for any tool below. Calling `help()` with no arguments returns this index.

- **append_note** — Add content to the END of an existing markdown note in a single call (returns `{ path, vault, bytes_written, inline }` — additive, so active mode needs no opt-in flag; a separator newline matching the file's LF/CRLF convention is added only when the file does not already end with one; `inline: true` fuses onto the last line; does not create missing notes). Writes directly to the vault filesystem, so no content-size cap.
- **backlinks** — Return the flat ordered list of every source note that references a target Markdown note (returns `{ count, backlinks: [{ source, count? }], truncated? }` — link-graph primitive; inverse of [`links`](./links.md); `with_counts: true` decorates entries with per-source multiplicity; `total: true` returns count only and bypasses the implicit 1000-source cap per the 2026-05-17 Q1 clarification; `limit` 1..10000 overrides the cap; `.md`-only source corpus per Q2; self-references included).
- **bases** — Enumerate every Obsidian Bases (`.base`) file in the vault (returns `{ bases: string[], count }` — paths sorted lexicographically, no truncation; an empty vault returns `count: 0`; optional `vault` is accepted but currently ignored by the CLI).
- **context_search** — Return each match of a literal phrase in a vault as a single entry carrying file path, 1-based line number, and the matching line's text (returns `{ count, matches: [{ path, line, text }], truncated? }` — eighteenth typed-tool wrap; dedicated per-line-context primitive; vault-scoped surface; collapses the "find file → read file → locate line" grep-style three-call pattern to one call; preferred over `search` with `context_lines=true`).
- **create_base** — Create a new item (Markdown note) within an Obsidian Bases (`.base`) file (returns `{ path, name }` with the actual filename — the CLI auto-increments on collision; `content` capped at 3072 UTF-16 code units; `view` is not validated by the CLI).
- **delete** — Delete a note from an Obsidian vault. Default sends the file to the OS trash (recoverable); `permanent: true` is irreversible.
- **files** — List files directly inside a vault folder (returns `{ count, paths }` — non-recursive folder-scoped enumeration, sub-folder + dotfile entries dropped, paths sorted by UTF-8 byte order; supports `total: true` for count-only mode).
- **find_and_replace** — Preview-then-commit find-and-replace across a vault, a sub-folder, or a single note (default call returns a preview of every occurrence; `commit: true` re-scans, checks for drift, and rewrites the matches on disk; literal or ECMAScript-regex `mode`; fenced code and HTML comments skipped by default; bounded by `OBSIDIAN_FIND_REPLACE_MAX_OCCURRENCES`, default 500). Default scope is vault-wide — narrow it deliberately and preview first.
- **find_by_property** — Find notes whose frontmatter property matches a given value (returns `{ count, paths }` — the value→file inverse of `read_property`).
- **get_active_file** — Report the active file Obsidian currently has focused (returns `{ active: { path, name, basename, extension } | null }` — the read counterpart of `open_file`; `target_mode: "active"` reads the focused vault, `target_mode: "specific"` + `vault` reads a named vault cross-vault; no active file is a `{ active: null }` success, never `ERR_NO_ACTIVE_FILE`; file-only, pure read).
- **help** — Look up full Markdown documentation for any registered MCP tool.
- **links** — Return the flat ordered list of every outgoing link in a Markdown note (returns `{ count, links: [{ target, line, kind, displayText? }] }` — link-graph primitive; frontmatter-declared wikilinks intermingled in source order; closed `{wikilink, embed, markdown}` kind enum; `total: true` switches to count-only mode).
- **list_notes** — _(documentation pending — owned by a future BI)_.
- **list_vaults** — _(documentation pending — owned by a future BI)_.
- **move** — Move a note in a vault (optionally renaming); honours the vault's auto-update-links setting.
- **obsidian_exec** — Invoke any Obsidian Integrated CLI subcommand.
- **open_file** — Make an existing vault file (note, canvas, PDF, image, attachment) the focused, visible, active file in Obsidian (opens in the named `vault` whether it is focused, open in the background, or closed-but-registered, and moves focus there; reports whether a new tab was created, an existing tab reused, or the active tab used; `new_tab` opt-in).
- **outline** — Return the flat ordered list of every heading in a Markdown note (returns `{ count, headings: [{ level, text, line }] }` — structural-discovery primitive; `total: true` switches to count-only mode).
- **patch_block** — Surgically replace the body tied to a named `^block-id` block-reference marker inside a markdown note (the marker and every byte outside the block stay unchanged; recognises paragraph, list-item, and separately-placed block shapes; first match wins on duplicate ids).
- **patch_heading** — Surgically rewrite the body under a named heading, addressed by its full hierarchical path (three placement modes: `append` at the end of the heading's reach, `prepend` right after the heading line, `replace` the direct body while preserving child sections; fails with `HEADING_RACE` if the section moves between read and write).
- **paths** — Recursive flat path list under a vault folder (returns `{ count, paths: string[] }` — folder entries end with `/`; optional `folder`, `depth`, `ext`; `total: true` switches to count-only mode).
- **pattern_search** — Scan every Markdown note in a vault (or under a named sub-folder) for an ECMAScript-regex pattern and return per-occurrence entries with `(path, line, offset, match, text)` (returns `{ count, matches: [{path, line, offset, match, text}], truncated? }` — regex companion to [`context_search`](./context_search.md) which is keyword-only; sixteenth typed-tool wrap; `case_sensitive` **defaults to `true`** — flips from `context_search`'s case-insensitive default per spec FR-007; `text` capped at 500 UTF-16 + `…` marker; `match` substring NEVER capped; zero-length matches skipped).
- **prepend** — Prepend `content` at the LOGICAL top of an existing markdown note in a single call — frontmatter-aware insertion (the prepended content lands AFTER any YAML frontmatter, preserving the frontmatter byte-for-byte); default-separator behaviour with FR-006a "content's trailing newline IS the separator" symmetric; optional `inline: true` fuses onto the existing leading body line. Content cap 3072 UTF-16 code units (lowered from 24576 in BI-047 after larger writes left the Obsidian GUI degraded; use `write_note` for longer content). CLI-wraps the upstream `obsidian prepend` subcommand (cohort divergence from sibling `append_note`'s fs-direct pipeline — the frontmatter-aware operation defers detection to upstream per FR-005b).
- **properties** — List every distinct frontmatter property name in a vault with per-property note counts (returns `{ count, properties: [{ name, noteCount }] }` — vault-wide structural-discovery primitive; case-insensitive-primary + byte-tiebreak sort places case-distinct duplicates adjacent; `total: true` switches to count-only mode).
- **query_base** — Run a named view from an Obsidian Bases (`.base`) file (returns `{ columns, rows, truncated, total_rows? }` — the reserved row-locator `path` is always `columns[0]`, and a view column named `path` is renamed `path_view`; capped at 1000 rows with `truncated` / `total_rows`).
- **read** — Read a note's raw text from an Obsidian vault by file (wikilink), path, or active focus.
- **read_heading** — Read the body of a single named heading from a vault note (returns `{ content: string }` — replaces full-file `read` plus client-side Markdown parse for the section-extraction case).
- **read_property** — Read a single named frontmatter property from a vault note (returns `{ value, type }` with native YAML types preserved).
- **rename** — Rename a `.md` note in place; honours the vault's auto-update-links setting.
- **search** — Vault-wide literal substring search returning just the matching file paths (returns `{ count, paths }` — lightest payload of the search tools; `context_lines: true` is deprecated in favour of [`context_search`](./context_search.md)).
- **search_vault** — _(documentation pending — owned by a future BI)_.
- **set_property** — Write a single named frontmatter property to a vault note (returns `{ written: true, path, name }` — surgical single-property write, the symmetric write companion to `read_property`).
- **smart_connections_query** — Return the typed list of semantically-nearest block-level matches in a vault for a free-text natural-language query via the Smart Connections plugin (returns `{ count, matches: [{ path, headingPath, score }] }` — plugin-backed query primitive; sibling to `smart_connections_similar`; flat schema with optional `vault?`; `total: true` switches to count-only mode; `limit` 1..100 default 20).
- **smart_connections_similar** — Return the typed list of semantically-similar block-level matches for a single source note via the Smart Connections plugin (returns `{ count, matches: [{ path, headingPath, score }] }` — plugin-backed similarity primitive; requires the Smart Connections plugin to be installed and indexed; `total: true` switches to count-only mode; `limit` 1..100 default 20).
- **tag** — Return the vault-relative paths of every Markdown note carrying a given tag (returns `{ count, paths: string[] }` in default mode, or a bare integer in count-only mode — tag-index retrieval primitive; case-insensitive matching via wrapper-side ASCII lower-fold; hierarchical child-tag subsumption with segment-bounded precision; both body inline tags and frontmatter tag arrays contribute; `total: true` switches to count-only mode).
- **views_base** — List the views defined inside an Obsidian Bases (`.base`) file (returns `{ views, count }` — pass `base_path` to name a Base, which is focused as a side effect, or omit it to read the Base currently open in Obsidian).
- **write_note** — Create a note in an Obsidian vault, or overwrite an existing one with `overwrite: true`. Writes directly to the vault filesystem, so there is no content-size cap; active mode requires `overwrite: true`. (An earlier version of this entry said it wraps the CLI's `create` subcommand, which stopped being true when ADR-009 moved writes off the CLI in 0.3.0.)
